核心原理
SCUM 定时公告 = 固定文件SCUM/Saved/Config/WindowsServer/Notifications.json你前端只做：读取这个 JSON → 可视化表单编辑 → 保存覆盖回去服务器不用重启，立马生效。
一、标准数据结构（前端固定死这个格式）
原生官方标准格式，只能用这套，不能乱改字段：
json
{
  "Notifications": [
    {
      "day": "Everyday",
      "time": "00:00-23:59",
      "wait": 10,
      "message": "服务器禁止开挂、炸家、恶意辱骂",
      "color": "255,255,0",
      "duration": 8
    }
  ]
}
字段含义（前端每个控件对应一个）：
day ：生效周期
Everyday 每天
Monday-Friday 工作日
Weekend 周末
time ：时间段 格式 HH:MM-HH:MM
wait ：循环间隔 分钟
message ：公告文字
color ：RGB 逗号分隔 红,绿,蓝
duration ：弹窗显示秒数
二、可视化前端页面布局（直接照抄做 UI）
页面模块
标题：定时公告管理
功能按钮区
新增公告
保存配置
刷新读取
公告列表（每条一条卡片）
无数据时：空白提示 + 一键初始化模板
单条公告 可视化控件搭配
每条公告一行 / 一张卡片，包含：
下拉选择：周期（每天 / 工作日 / 周末）
时间选择器：开始时间 + 结束时间
前端自动拼接成 HH:MM-HH:MM
输入框：循环间隔（分钟）
文本域：公告内容
颜色选择器
选颜色 → 前端自动转 R,G,B
输入框：弹窗显示秒数
操作按钮：删除、上移、下移
三、前端交互逻辑（重点）
1. 读取流程
前端请求后端接口→ 后端读取 Notifications.json→ 返回 json 数组→ 前端循环渲染列表
2. 编辑流程
用户改任何表单→ 前端实时绑定到数组对象→ 点【保存】→ 把完整 JSON 传给后端→ 后端覆盖写入原 Notifications.json
3. 自动兼容处理
如果服务器没有这个文件：
前端给默认 3 条模板，后端直接生成文件
中文不乱码：后端写入强制 UTF-8

覆盖写入 Notifications.json（UTF-8）
